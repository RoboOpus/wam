# RoboOpus 知识库参考案例与模板调研

> 调研日期：2026-09-08  
> 统计口径：GitHub 公共仓库页面与公开 API；Star、Fork 和活跃时间是动态快照。  
> 目标：寻找可借鉴的信息架构、论文流水线、WAM 内容源、机器人学习路线、硬件索引与项目站模板。

## 1. 结论

RoboOpus 不需要复制某一个现成项目，而应组合四类最佳实践：

1. **论文自动发现与排序**：借鉴 Paper Leaderboard 的配置、去重、打分、数据与前端分离。
2. **WAM 专业分类与论文源**：以两篇 2026 WAM 综述及其维护仓库作为主索引，建立自己的交叉分类与中文阅读路线。
3. **从链接列表进化为知识页**：借鉴 `Robotics_Notebooks` 的互链页面、路线、schema、sources 和 tests，但先不上复杂知识图谱。
4. **项目站发布**：MVP 使用 Vinext/React 的静态导出，以便做更鲜明的研究索引首页；内容规模扩大后再评估 Astro Starlight 的文档导航与全文搜索。

当前项目仓库命名为 `RoboOpus/wam`，目标项目站为 `https://roboopus.github.io/wam/`。本项目不创建、不修改 `RoboOpus/RoboOpus.github.io`。

## 2. 调研方法

本轮使用和交叉组合了这些 GitHub 检索词：

- `awesome embodied ai`
- `awesome robot learning`
- `awesome robotics manipulation`
- `awesome VLA papers`
- `world action model robotics`
- `world model robot manipulation`
- `robot paper leaderboard arxiv`
- `embodied AI guide roadmap`
- `robotics knowledge base graph`
- `open source robots hardware`
- `open source robotic arms`
- `Astro academic GitHub Pages`
- `Starlight knowledge base GitHub Pages`

筛选时优先考虑：与目标板块的直接相关性、结构化程度、是否持续更新、是否有机器可读数据、是否有部署示例、许可证是否清晰。Star 只反映传播度，不等于内容质量。

## 5. 核心案例拆解

### 5.1 Paper Leaderboard 系列：借自动流水线，不照搬分数

建议复用的思想：

- 查询、分类和相关性词表配置化；
- 原始论文元数据与网站展示分离；
- 全量抓取、增量刷新、重新评分、前端重建分成独立命令；
- 每条记录保存来源、时间和评分分解；
- 榜单仅作发现入口，最终精选仍经过人工阅读。

需要修改之处：WAM 是新兴领域，引用数会系统性偏向旧论文，因此不能把 citation 作为主分。第一版建议把“与 WAM 定义的匹配度、真实机器人实验、开源代码/模型、评测完整性、创新性”放在引用数之前。

### 5.2 两个 WAM 综述仓库：双分类交叉校验

[OpenMOSS/Awesome-WAM](https://github.com/OpenMOSS/Awesome-WAM) 采用 Cascaded / Joint WAM 主分类，并继续细分自回归、扩散、显式未来、隐式未来和流间耦合；同时带逐篇阅读 blog、benchmark 页面和自动摘要思路。

[world-action-models/awesome-world-action-models](https://github.com/world-action-models/awesome-world-action-models) 给出更操作化的纳入规则：预测出的未来必须进入动作生成、评分、训练或检查路径；并按 Render-and-Decode、Latent-Only、Video-Generation-Free 分类。

RoboOpus 的差异化价值不是再复制一遍列表，而是：

- 给出两套 taxonomy 的映射；
- 为中文读者建立从 World Model 到 WAM 的阅读路线；
- 加入论文之间的 `builds_on`、`contrasts_with`、`uses_backbone`、`evaluated_on` 关系；
- 明确记录是否真实机器人、是否开源、推理频率、硬件成本与失败模式；
- 对新论文保留“候选—已核验—已精读—已复现”状态。

### 5.3 Robotics_Notebooks：长期形态参考

它最有价值的地方不是链接数量，而是把页面作为有依赖关系的知识节点，并同时维护路线、技术地图、schema、sources、脚本和测试。RoboOpus 可以分阶段吸收：

1. 现在：Markdown 页面 + `related` 链接 + 阅读路线。
2. 稳定后：为论文、方法、数据集、benchmark 和硬件定义 schema。
3. 内容达到数百页后：由页面互链自动生成知识图谱，而不是人工维护第二份图数据。

### 5.4 Astro Starlight：适合内容规模化后的升级

当前两篇论文 MVP 已用 Vinext/React 建站并静态导出。论文数量增长、需要侧栏和全文搜索后，可迁移或接入 Starlight。无论采用哪种框架，项目站都必须处理仓库子路径：

```js
export default defineConfig({
  site: 'https://roboopus.github.io',
  base: '/wam',
});
```

不要把首轮精力花在复杂首页、动态后端或向量数据库上。Markdown、导航、全文搜索和 Git 历史足以支撑前几百篇论文。

## 6. 可直接采用、需要改造、暂不采用

| 决策 | 内容 |
|---|---|
| 直接采用 | Markdown 作为事实层；来源 URL 与抓取时间；论文/代码/项目页分离；候选内容经 PR 审核；项目站部署 |
| 改造后采用 | Paper Leaderboard 的评分框架；Awesome 列表的分类；Paper2Blog 的摘要结构；Robotics_Notebooks 的关系和路线 |
| 暂不采用 | 自动合并 AI 内容；只按 citation/star 排名；镜像论文全文；一开始就上 Neo4j/多 Agent/复杂 RAG；批量绕过平台登录或反爬 |

## 8. 许可证与引用边界

- Apache-2.0、MIT、BSD、CC0 等只覆盖各仓库明确声明的代码或文本范围，不自动覆盖其链接的论文、图片、视频和第三方数据。
- “未检测到/未识别许可证”的仓库只借鉴公开可观察的信息架构和事实链接，不复制 README 文本、图像或代码。
- 每个 RoboOpus 页面应使用原创中文总结，并回链论文、项目页和代码仓库。
- 自动采集只保存元数据、短摘要、引用和必要的缩略信息；论文 PDF 与登录后内容不进入公开仓库。
